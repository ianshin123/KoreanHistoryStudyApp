## 2. 교과서 요소 분석 — "무엇을 데이터로 만들 것인가"

펼침면 하나를 뜯어보면 아래 9가지 요소가 반복된다. **전부 출제 대상이되, 가중치가 다르다.**

| # | 요소 | 예시 | 중요도 |
|---|---|---|---|
| 1 | 본문 소제목 | "민족주의 세력이 실력 양성 운동을 전개하다" | ★★★ |
| 2 | 본문 서술 + **굵은 키워드** | 물산 장려 운동, 민립 대학 설립 운동, 자치 운동 | ★★★ |
| 3 | 사료 박스 (원문 + 출처) | 〈민족적 경륜〉, 제1차 조선 교육령, 윌슨 14개조 | ★★ |
| 4 | 지도 · 도표 · 그래프 | 1920년대 국내 민족 운동의 흐름 | ★★ |
| 5 | 사진 자료 + 캡션 | "조선 물산 장려회 포스터" | ★★ |
| 6 | 인물 사진 + 생몰년 | 이광수(1892–1950) | ★ |
| 7 | 여백 용어 풀이 | 본위, 야학, 민족 자결주의 | ★ |
| 8 | 역사탐구 "탐구해 보자!" (자료+발문) | 소설 〈만세전〉으로 본 무단 통치 | ★ |
| 9 | 배움길 / 학습 목표 / 배움 노트 | 단원 도입·마무리 | ★★ |

**핵심 문제의식(사용자 요구):**
> "본문·중점 내용에서 많이 나오지만, 그림·인물·사료 발췌도 몇 문제는 나온다.
> 몇 문제 안 나온다고 그걸 놓치고 공부 안 할 수는 없다."

→ 이 앱의 **설계 제1원칙**은 다음과 같이 잡는다.

### 설계 제1원칙: 출제 가중치 ≠ 학습 커버리지

- **출제 비중**은 중요도를 따라간다 (본문 많이, 주변부 적게).
- 그러나 **커버리지는 100%** 다. 범위 안의 모든 그림·인물·용어·사료가 **최소 1문항 이상** 반드시 존재한다.
- 이를 보장하기 위해 **주변부 문항은 구조화된 데이터에서 자동 생성**한다.
  사람이 문제를 뽑다 보면 반드시 빠지는 게 생기지만, 스크립트는 빠뜨리지 않는다.
- 앱에 **「커버리지 보드」** 화면을 둔다. 범위 내 전 항목을 격자로 깔고
  `미학습 / 학습함 / 틀림 / 익힘` 상태를 색으로 보여준다.
  **회색 칸이 0개가 되는 것**이 시험 준비 완료의 정의.

## 3. 결정적 발견 — 콘텐츠 디지털화가 "자동화 가능"하다

이 작업이 무섭게 느껴지는 이유는 "교과서 78쪽을 손으로 옮겨 적어야 하나?" 이기 때문인데,
조사 결과 **그럴 필요가 없다.**

이 PDF는 스캔 이미지가 아니라 **텍스트 레이어가 살아 있는 원본 PDF**다. 확인된 사항:

1. **OCR 불필요 / 오타 0%** — 한글 텍스트를 좌표와 함께 그대로 뽑을 수 있다.
   (`poppler-data` 설치로 Adobe-KR CMap 문제 해결 완료)
2. **구조가 글꼴·색·크기로 구분된다** — 자동 분류가 가능하다.

   | 요소 | 글꼴 | 크기 | 색 |
   |---|---|---|---|
   | 본문 소제목 | `SDGothicNeoc-eSm` | 7.2 | `#8d4b37` (갈색) |
   | 본문 | `YDVYMjO13` | 7.2 | `#231f20` |
   | 사료 본문 | `SDBook-aLt` | 6.2 | `#231f20` |
   | 캡션·여백 용어 | — | 4.0–5.4 | — |
   | 말풍선(친구 대사) | `GangwonEduSaeeum` | 7.4 | — |

3. **그림 자동 추출 가능** — PyMuPDF로 페이지 내 모든 이미지의 **바운딩 박스**를 얻을 수 있다.
   (예: 44–45쪽에서 유효 이미지 12개 좌표 추출 성공)
   → 고해상도 렌더 후 좌표로 잘라내면 **그림 파일이 자동 생성**된다.
   사람이 할 일은 "이 그림에 어떤 캡션이 붙는가 / 중요도 몇인가" 라벨링뿐.

**결론:** 78쪽 전량 디지털화는 손 타이핑이 아니라
**「스크립트로 1차 추출 → 펼침면 이미지 보면서 검수·라벨링」** 작업이다.
펼침면당 검수 시간이 관건이고, 이게 전체 일정의 대부분을 차지한다.

## 6. 기술 스택 — 결정과 근거

| 항목 | 결정 | 근거 |
|---|---|---|
| 프레임워크 | **없음 (Vanilla JS ES Modules)** | 빌드 단계가 없으면 GitHub Pages가 파일을 그대로 서빙한다. 배포 실패 지점이 사라지고, 나중에 본인이 직접 문제/오타를 고치기 쉽다. |
| CSS | **순수 CSS** (CDN 금지) | PWA 오프라인 요건. Tailwind CDN은 네트워크 없으면 깨진다. |
| 데이터 | **정적 JSON** | 서버 불필요. |
| 문항 생성 | **사전 생성 후 커밋** | 런타임 AI 호출은 API 키가 필요하고, 정적 사이트에 키를 넣을 수 없다. 오프라인도 불가. |
| 서술형 채점 | **루브릭 자가 채점** | 위와 동일 이유. 모범답안 + "이 요소가 들어갔는가" 체크리스트가 실제 시험 채점 기준과도 더 가깝다. |
| 저장 | **localStorage + JSON 내보내기** | 백엔드 없음. iOS PWA는 저장소가 지워질 수 있어 백업 기능을 반드시 둔다. |
| PWA | `manifest.webmanifest` + `sw.js` (precache) | "홈 화면에 추가" + 오프라인 학습. |
| 배포 | GitHub Pages (브랜치 루트) | |

## 7. 진행 절차 (단계별)

각 단계는 **"끝났는지 눈으로 확인할 수 있는 산출물"** 을 갖는다.
**Phase 2에서 한 번 멈추고 실물을 본 뒤** 나머지를 진행한다.

### Phase 0 — 조사 · 설계 ✅ *(완료)*
- PDF 구조 분석, 범위 확정, 요소 유형 도출, 추출 가능성 검증
- 산출물: 이 문서

### Phase 1 — 추출 파이프라인 구축
- `tools/extract.py` : 펼침면 → 블록(JSON) 1차 자동 분류
- `tools/crop.py` : 그림 바운딩 박스 → 이미지 크롭 + 펼침면 원본 렌더
- 산출물: **10–15쪽(01 대주제)의 자동 추출 결과**. 정확도가 어느 정도인지 실측.
- 판단 지점: 자동 분류 정확도가 낮으면 여기서 수작업 비중을 다시 잡는다.

### Phase 2 — 🔴 파일럿 (여기서 한 번 멈춘다)
소단원 **딱 1개**(`Ⅰ-01-2 일제의 '문화 정치'`, 13–15쪽)로 **전 과정을 끝까지** 통과시킨다.
- 콘텐츠 JSON 완성 (본문·사료·그림·인물·용어 전부)
- 앱 셸 + 학습 모드 + 퀴즈 모드 최소 구현
- PWA 설정, GitHub Pages 배포, 아이폰 홈 화면 추가까지 실제로 해 본다
- **산출물: 실제로 손에 쥐고 써 볼 수 있는 앱**
- **여기서 피드백을 받고** 글자 크기·문항 난이도·화면 구성을 확정한다.
  이 단계에서 바꾸면 싸고, 20개 소단원 다 만들고 바꾸면 비싸다.

### Phase 3 — 앱 기능 완성
- SRS, 커버리지 보드, 구석구석 모드, 오답노트, 연표, 데이터 백업, 검색
- 산출물: 데이터만 채우면 되는 상태의 완성된 앱

### Phase 4 — 콘텐츠 전량 디지털화
- 39개 펼침면을 **대주제 단위로 배치 처리** (Ⅰ-01 → Ⅰ-02 → … → Ⅱ-01)
- 각 배치마다: 자동 추출 → 펼침면 이미지 대조 검수 → 중요도 라벨링 → 커밋
- 산출물: `data/sections/*.json` 20개 + 그림 ~300장
- **배치마다 즉시 배포**되므로, 전체가 끝나기 전에도 앞부분부터 공부 시작 가능

### Phase 5 — 문항 제작
- 자동 생성: 키워드 빈칸 / 용어 단답 / 인물 단답 / 이미지 식별 / 사료 출처
  → 주변부 100% 커버리지 보장
- 직접 작성: 본문 핵심 4지선다 + OX + 서술형
- 목표 분량: 소단원당 25–40문항 → **전체 약 500–800문항**
- 산출물: `data/questions/*.json`

### Phase 6 — 마감
- 전범위 모의고사 모드, D-day 역산 복습 스케줄
- 실사용하며 오탈자·오답 수정 (앱 안에 「문항 신고」 → 파일 위치 안내)

## 8. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| **작업량이 크다** (39 펼침면) | Phase 4를 대주제 단위로 쪼개고 배치마다 배포. 전량 완성 전에도 학습 가능. 시험이 임박하면 범위 앞쪽부터 우선. |
| 자동 추출 오류 | 펼침면 원본 이미지를 앱에 같이 넣어 **「원본 보기」** 를 항상 제공. 데이터가 틀려도 원본으로 확인 가능. |

## 9. 결정이 필요한 사항

1. **저장소 공개 여부** — GitHub Pages는 공개 저장소면 무료지만 교과서 본문·그림이 인터넷에 공개된다. 비공개 저장소로 Pages를 쓰려면 GitHub Pro(유료)가 필요하다.
2. **시험일(D-day)** — 복습 스케줄 압축과 Phase 4 배치 순서 우선순위에 직접 영향.
3. **서술형 비중** — 실제 시험에 서술형이 있는지, 있다면 몇 문항인지.
4. **Phase 2 파일럿 대상 소단원** — 기본 제안은 `Ⅰ-01-2 일제의 '문화 정치'`(13–15쪽). 사료·인물 사진·탐구 활동이 모두 들어 있어 전 요소를 한 번에 검증하기 좋다.
