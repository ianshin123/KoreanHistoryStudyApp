| 7 | 여백 용어 풀이 | 본위, 야학, 민족 자결주의 | ★ |
| 8 | 역사탐구 "탐구해 보자!" (자료+발문) | 소설 〈만세전〉으로 본 무단 통치 | ★ |
| 9 | 배움길 / 학습 목표 / 배움 노트 | 단원 도입·마무리 | ★★ |

### 설계 제1원칙: 출제 가중치 ≠ 학습 커버리지

> "본문에서 많이 나오지만 그림·인물·사료 발췌도 몇 문제는 나온다.
> 몇 문제 안 나온다고 그걸 놓치고 공부 안 할 수는 없다."

- **출제 비중**은 중요도를 따라간다 (본문 많이, 주변부 적게).
- 그러나 **커버리지는 100%** — 범위 내 모든 그림·인물·용어·사료가 **최소 1문항 이상** 반드시 존재한다.
- 이를 보장하기 위해 **주변부 문항은 구조화 데이터에서 자동 생성**한다.
  사람이 뽑으면 반드시 빠지는 게 생기지만, 스크립트는 빠뜨리지 않는다.
- **「커버리지 보드」** 화면: 범위 내 전 항목을 격자로 깔고 `미학습 / 학습함 / 틀림 / 익힘` 을 색으로 표시.
  **회색 칸 0개** = 시험 준비 완료의 정의.

## 3. 핵심 설계 — "단원 범위" vs "다양한 정리축" 충돌 해소

네가 정확히 짚은 문제다. 정리하면 이렇게 충돌한다.

- **시험은 단원 범위로 나온다** → 문제는 단원 단위로 풀어야 한다.
- **이해는 시대순·인물별이 낫다** → 학습은 다른 축이 낫다.
- 두 축을 따로 만들면 **"방금 공부한 걸 그대로 문제로"** 가 안 된다. 앱이 두 쪽으로 갈라진다.

### 해법: 단원을 '폴더'가 아니라 '태그'로 취급한다

교과서 위치를 폴더 계층으로 박아 넣는 순간 다른 축이 불가능해진다.
그래서 **모든 학습 원자(블록)에 여러 축의 좌표를 동시에 붙인다.**

```jsonc
// 학습 원자 하나 = 교과서 블록 하나
{
  "id": "1-03-4#b07",
  "loc":    { "unit": "Ⅰ", "topic": "03", "section": "4", "page": 42 },  // 교과서 위치 (1개, 고정)
  "era":    { "year": 1923, "span": [1920, 1924] },                      // 시대순 정렬 키
  "events": ["물산 장려 운동"],                                            // 사건 태그 (N개)
  "people": ["조만식"],                                                   // 인물 태그 (N개)
  "themes": ["실력 양성 운동", "민족 운동의 분화"],                          // 주제 태그 (N개)
  "tier":   3
}
```

그리고 **범위(Scope)를 축과 무관한 단일 개념으로 통일**한다.

```
Scope = { by: "unit" | "era" | "event" | "person" | "theme" | "custom",
          keys: [...] }

resolve(Scope) ──▶ Set<블록 ID> ──▶ Set<문항 ID>
```

어떤 축으로 고르든 결국 **같은 형태의 집합**으로 환원되므로,
**학습 엔진도 하나, 퀴즈 엔진도 하나**면 된다. 축이 늘어나도 엔진은 안 늘어난다.

### 이게 UI에서 어떻게 보이나

화면 최상단에 **범위 칩(Scope Chip)** 하나가 항상 떠 있다. 어느 화면에서든 같은 칩이다.

```
┌────────────────────────────────────────────┐
│  📍 Ⅰ-03 다양한 민족 운동의 전개  (30–47쪽) ▾ │   ← 누르면 범위 선택 시트
└────────────────────────────────────────────┘

범위 선택 시트
 [ 단원 ] [ 시대 ] [ 사건 ] [ 인물 ] [ 주제 ] [ 내 범위 ]
   ▲ 기본 탭

 단원 탭 (트리 체크박스)
   ☑ Ⅰ. 일제 식민 통치와 민족 운동
      ☐ 01 제국주의 질서와 일제의 식민 통치 정책
      ☑ 03 다양한 민족 운동의 전개
         ☑ 1  1910년대 민족 운동과 3·1 운동
         ☑ 2  대한민국 임시 정부의 수립과 활동
         …
   ☐ Ⅱ. 대한민국의 발전

 ─────────────────────────────────────────
 선택: 5개 소단원 · 블록 142개 · 문항 187개
 [ 이 범위 학습 ]  [ 이 범위 문제풀기 ]  [ 커버리지 ]
```

**핵심 사용성:** 범위를 한 번 정하면 학습·퀴즈·커버리지가 **그 범위를 그대로 공유**한다.
"방금 공부한 데까지만 문제 풀기"가 버튼 하나로 된다. 범위를 두 번 고를 일이 없다.

### 정리축은 '범위'가 아니라 '진열 방식'이다

축 충돌이 생기는 이유는 정리축과 범위를 같은 것으로 착각해서다. 분리하면 깔끔해진다.

- **범위(Scope)** = *무엇을* 볼 것인가 → 학습·퀴즈 공유
- **정렬축(Order)** = *어떤 순서로* 볼 것인가 → **학습 모드 안에서만** 바뀜

학습 모드 안에 정렬 토글:

| 정렬축 | 진열 방식 | 언제 쓰나 |
|---|---|---|
| **교과서순** (기본) | 쪽 순서 그대로, 원문 구조 유지 | 처음 이해할 때, 시험 직전 |
| **연표순** | 연도 오름차순, 연도 헤더로 그룹 | 흐름·순서 잡을 때 |
| **사건별** | 사건 카드 → 관련 블록 모음 | 사건 하나를 통으로 정리 |
| **인물별** | 인물 카드 → 등장하는 모든 대목 | 인물 종합 문제 대비 |
| **주제별** | 통치정책 / 경제수탈 / 무장투쟁 / 사회문화 … | 유형별 비교 |

### 인물·사건축이 실제로 강력한 이유

교과서순으로는 절대 안 모이는 게 모인다. 예를 들어 **김구**는 범위 안에서 이렇게 흩어져 있다.

```
 34쪽  대한민국 임시 정부의 수립과 활동
 37쪽  무장 투쟁과 의열 투쟁 (한인 애국단)
 63쪽  한중 연대와 민족 운동 세력의 결집
 66쪽  건국 준비 활동 (한국광복군)
 82쪽  통일 정부 수립을 위한 노력 (남북 협상) ← 다른 대단원!
```

교과서를 순서대로 다섯 번 읽어도 이게 한 화면에 모이지 않는다.
그런데 **시험에는 "김구의 활동으로 옳은 것은?" 같은 인물 종합 문제가 나온다.**
인물축은 그 대비를 위한 것이다. 사건축(예: 3·1 운동 → 원인·전개·영향·임정 수립으로 연결)도 같다.

### 충돌 회피의 실질: 기본값을 절대 뺏지 않는다

- 앱 기본값은 **항상 「단원 범위 + 교과서순」**. 시험이 그렇게 나오니까.
- 다른 축은 **「다른 각도로 보기」** 버튼으로만 진입. 기본 동선을 건드리지 않는다.
- 3주 일정에 맞춘 **단계별 추천**을 홈 화면이 안내한다.

| 시기 | 추천 범위 | 추천 정렬축 | 추천 활동 |
|---|---|---|---|
| 1주차 (이해) | 중단원 하나씩 | 교과서순 | 학습 → 소단원 퀴즈 |
| 2주차 (정착) | 대단원 | 교과서순 + 연표순 | SRS 복습 + 구석구석 모드 |
| 3주차 (종합) | 전범위 | 인물별 · 사건별 | 모의고사 + 오답노트 |
| 직전 (점검) | 전범위 | 교과서순 | 커버리지 보드 회색 칸 지우기 |

## 4. 문항 설계 — 실제 모의고사처럼

> "사료나 그래프, 그림 주고서 이 사건에 대해 옳거나 옳지 않은 것은? 이런 게 많이 나와."

맞다. 그래서 문항을 **단순 암기형이 아니라 자료 제시형 중심**으로 설계한다.

### 문항 형식 (format)

| format | 발문 예시 | 자료 |
|---|---|---|
| `source-pos` | "(가) 자료와 관련된 운동에 대한 설명으로 **옳은 것은?**" | 사료 |
| `source-neg` | "밑줄 친 '이 정책'에 대한 설명으로 **옳지 않은 것은?**" | 사료 |
| `image-id` | "다음 사진의 자료로 옳은 것은?" | 사진·포스터 |
| `image-ctx` | "다음 포스터가 제작된 시기의 사실로 옳은 것은?" | 사진 |
| `graph` | "다음 그래프에 나타난 변화의 배경으로 옳은 것은?" | 그래프·통계 |
| `map` | "지도에 표시된 지역에서 전개된 활동은?" | 지도 |
| `compare` | "(가), (나)를 주장한 세력에 대한 설명으로 옳은 것은?" | 자료 2개 |
| `order` | "(가)~(다)를 일어난 순서대로 나열한 것은?" | 사건 3~5개 |
| `timeline` | "밑줄 친 사건이 일어난 시기를 연표에서 고르면?" | 연표 (가)~(마) |
| `cloze` | 빈칸 채우기 | 본문 |
| `short` | 단답 | 인물·용어 |
| `essay` | 서술형 (루브릭) | 본문 중점 |

### 문항 스키마

```jsonc
{
  "id": "q-1-03-4-012",
  "section": "1-03-4",
  "format": "compare",
  "negative": false,
  "tier": 3,
  "origin": "hand",                  // hand | auto
  "stimulus": [
    { "label": "(가)", "kind": "source",
      "text": "우리는 '내 살림 내 것으로'…",
      "cite": "조선 물산 장려회 궐기문, 1923." },
    { "label": "(나)", "kind": "source",
      "text": "자작자급은 조선인 자본가 계급의 이익을…",
      "cite": "동아일보, 1923. 3. 20." }
  ],
  "stem": "(가), (나)의 주장을 편 세력에 대한 설명으로 옳은 것은?",
  "choices": ["…", "…", "…", "…", "…"],
  "answer": 2,
  "explain": "(가)는 민족주의 계열의 물산 장려 운동…",
  "distractors": {                   // 오답 하나하나 왜 틀렸는지
    "1": "민립 대학 설립 운동의 내용이다.",
    "3": "신간회는 1927년에 창립되었다."

**중요한 UI 디테일:** `negative: true` 인 문항은 실제 시험지처럼 **"옳지 <u>않은</u>"** 을 굵게·밑줄로 강조한다. 부정 발문을 놓쳐서 틀리는 건 실력 문제가 아니라 UI 문제니까.

### 서술형 처리

정적 사이트라 AI 채점이 불가능하다(API 키를 공개 저장소에 넣을 수 없고 오프라인도 안 됨).
대신 **실제 학교 채점 기준표와 같은 방식**으로 만든다 — 이게 오히려 시험 대비에 더 가깝다.

모범답안: …

  ☐ 친일파 양성·민족 분열 의도 언급     (2점)
  ☐ 헌병 경찰 → 보통 경찰 전환 언급     (1점)
  ☐ 경찰 수·예산은 오히려 증가 언급     (1점)

```

### 모의고사 모드

- 전범위(또는 지정 범위)에서 **실제 시험 구성비로 20문항 출제**
- 타이머 / 한 번에 제출 / 문항 번호판 / 나중에 볼 문항 체크
- 채점표 + 틀린 문항 자동 오답노트 등록 + 근거 본문 링크
- 출제 믹스 기본값 — 자료제시형 50% · 단순 개념 25% · 순서·시기 15% · 서술형 10%

## 5. 결정적 발견 — 콘텐츠 디지털화가 자동화 가능하다

이 작업이 무섭게 느껴지는 이유는 "교과서 78쪽을 손으로 옮겨 적어야 하나?" 이기 때문인데,
조사해 보니 **그럴 필요가 없다.**

이 PDF는 스캔 이미지가 아니라 **텍스트 레이어가 살아 있는 원본 PDF**다. 검증 완료:

1. **OCR 불필요 · 오타 0%** — 한글 텍스트를 좌표와 함께 그대로 추출 가능
   (`poppler-data` 설치로 Adobe-KR CMap 문제 해결 완료)
2. **구조가 글꼴·크기·색으로 구분된다** → 자동 분류 가능

   | 요소 | 글꼴 | 크기 | 색 |
   |---|---|---|---|
   | 본문 소제목 | `SDGothicNeoc-eSm` | 7.2 | `#8d4b37` (갈색) |
   | 본문 | `YDVYMjO13` | 7.2 | `#231f20` |
   | 사료 본문 | `SDBook-aLt` | 6.2 | `#231f20` |
   | 캡션·여백 용어 | — | 4.0–5.4 | — |
   | 말풍선(친구 대사) | `GangwonEduSaeeum` | 7.4 | — |

3. **그림 자동 추출 가능** — PyMuPDF로 페이지 내 모든 이미지의 **바운딩 박스**를 얻는다
   (44–45쪽에서 유효 이미지 12개 좌표 추출 성공)
   → 고해상도 렌더 후 좌표로 잘라내면 그림 파일이 자동 생성된다.
   사람이 할 일은 "이 그림의 캡션은 무엇이고 중요도는 몇인가" 라벨링뿐.

**결론:** 78쪽 전량 디지털화는 타이핑이 아니라
**「스크립트 1차 추출 → 펼침면 이미지 보며 검수·태깅」** 작업이다.
일정의 대부분은 검수·태깅 시간이고, 이건 대주제 단위로 쪼개서 병렬 진행할 수 있다.

## 7. 기술 스택 — 결정과 근거

| 항목 | 결정 | 근거 |
|---|---|---|
| 프레임워크 | **없음 (Vanilla JS ES Modules)** | 빌드 단계가 없으면 GitHub Pages가 파일을 그대로 서빙. 배포 실패 지점이 사라지고, 나중에 오타·오답을 직접 고치기 쉽다. |
| CSS | **순수 CSS** (CDN 금지) | 오프라인 요건. Tailwind CDN은 네트워크 없으면 깨진다. |
| 데이터 | **정적 JSON** | 서버 불필요. |
| 문항 | **사전 생성 후 커밋** | 런타임 AI 호출은 API 키가 필요하고 공개 저장소에 키를 넣을 수 없다. 오프라인도 불가. |
| 서술형 채점 | **루브릭 자가 채점** | 위와 동일. 실제 학교 채점 기준과도 더 가깝다. |
| 저장 | **localStorage + JSON 내보내기** | 백엔드 없음. iOS PWA는 저장소가 지워질 수 있어 백업 필수. |
| PWA | `manifest.webmanifest` + `sw.js` | "홈 화면에 추가" + 오프라인 학습 |
| 배포 | GitHub Pages (public, 브랜치 루트) | 무료 |

## 8. 진행 절차 — 3~4주 일정

Phase 4부터는 **배치마다 즉시 배포**되므로, 전체 완성 전에도 앞부분부터 공부를 시작할 수 있다.

|---|---|---|---|

### Phase 2 파일럿 상세 (제안)
